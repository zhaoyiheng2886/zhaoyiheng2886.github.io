# Astro 双流个人博客设计

## 目标

将现有 Jekyll Academic Pages 站点迁移为基于 Astro 的静态个人网站，同时服务三类内容：技术博客、人生记忆和研究成果。网站应保持单栏、纵向、文字优先的阅读体验，并以克制的编辑器气质表达极客感。

迁移完成后，作者应能通过 Markdown/MDX 写作，由 GitHub Actions 自动构建并继续发布到 `https://zhaoyiheng2886.github.io/`。

## 现状与迁移范围

旧站包含：

- 12 篇博客文章，其中 8 篇为 AIGC、论文精读或课程笔记，4 篇为求职日记；
- 2 条研究成果；
- 中英文 About 页面；
- 文章插图、头像、图标和论文附件；
- 一个浏览器内 Markdown 编辑器；
- Jekyll 生成的年份归档、标签、分类、作品、演讲、教学和简历页面。

迁移保留真实内容和仍有用途的功能。旧模板附带但没有实际个人内容的示例页面、演讲、教学、作品示例和冗余主题资源不进入新站。

## 信息架构

主导航固定为五个入口：

- `~/home`：个人简介、最新文章和统一时间流；
- `~/tech`：技术文章、论文精读、课程笔记；
- `~/memory`：人生回忆、求职日记和以后新增的生活记录；
- `~/research`：研究方向与发表成果；
- `~/about`：完整个人介绍和联系方式。

Markdown 编辑器迁移到 `/editor/`，但不出现在主导航。标签页位于 `/tags/`，搜索页位于 `/search/`。

首页采用统一时间流，不把技术与人生拆成两个互不关联的网站。每条内容通过 `TECH`、`MEMORY` 或 `RESEARCH` 类型标签区分，并按日期倒序排列。

网站默认语言为中文，技术名词和类型标签保留英文。中文个人介绍位于 `/about/`，英文个人介绍位于 `/en/about/`，两页提供明确的语言切换入口；旧 `/cn/` 地址跳转至 `/about/`。

## 技术架构

采用 Astro 6 和 Astro Cactus 的博客能力作为底座，但不直接照搬其页面外观。主要依赖保持精简：

- Astro Content Collections 管理文章和研究成果；
- Markdown/MDX 作为内容格式；
- Pagefind 提供构建后的静态搜索；
- Expressive Code 提供代码高亮；
- RSS、站点地图、robots.txt 和 Open Graph 图片在构建时生成；
- GitHub Actions 构建 `dist/` 并部署到 GitHub Pages。

网站无数据库、登录系统和服务器运行时。公开页面在构建期生成，以减少维护和安全成本。

## 内容模型

### 文章

文章集合使用以下字段：

- `title`：标题；
- `description`：摘要，用于列表和 SEO；
- `publishDate`：发布日期；
- `updatedDate`：可选更新时间；
- `kind`：`tech` 或 `memory`；
- `tags`：标签数组；
- `series`：可选系列名；
- `coverImage`：可选封面；
- `draft`：是否为草稿；
- `legacyPath`：需要保留的旧文章路径。

现有 AIGC、扩散模型和 CS224N 内容归类为 `tech`；四篇求职日记归类为 `memory`。现有文章正文和图片不做语义改写，只修正 Jekyll 专用语法、资源路径及必要的 Markdown 兼容问题。

### 研究成果

研究集合包含标题、日期、作者、发表状态、期刊或会议、链接、摘要及可选 PDF。旧站的两条 publication 数据迁移到该集合。

### 人生节点

独立的 `moments` 数据集合记录年份、日期、标题、地点、摘要和关联文章。第一版只建立结构，不虚构私人经历；没有真实内容时，页面提供克制的空状态说明。

## 路由与兼容

新文章使用可读的 `/tech/<slug>/` 或 `/memory/<slug>/` 地址。为已有文章额外生成其原始 `/posts/YYYY/MM/<slug>/` 路径，使用静态重定向页跳转到新地址，避免已分享链接失效。

保留以下入口或提供等价跳转：

- `/`；
- `/cn/`；
- `/publications/`；
- `/year-archive/`；
- `/tags/`；
- `/blog-editor/`。

两条研究成果原有的 `/publication/<slug>/` 地址也分别跳转到新研究成果详情或 `/research/` 中对应的锚点。

无法迁移且没有真实内容的旧示例页面返回定制 404，不继续携带 Academic Pages 的模板样例。

## 视觉系统

页面采用窄版单栏布局，正文最大宽度为 `45rem`，技术代码块可在桌面端适度突破正文宽度。移动端保持单列，不出现横向导航溢出。

色彩仅使用五个语义变量：

- `paper: #F4F5F2`：浅色背景；
- `ink: #15181D`：主要文字与深色背景；
- `graphite: #69707B`：次级文字；
- `signal: #5877D8`：唯一强调色；
- `line: #D9DCE1`：分隔线。

深色模式反转纸色与墨色关系，并保持信号蓝的可访问对比度。页面不使用渐变、玻璃效果、大面积阴影和装饰性圆角。

字体分工：

- 标题、导航、日期、标签和代码使用等宽字体栈；
- 中文长文使用系统宋体优先的衬线字体栈；
- 英文正文使用与中文衬线字体协调的系统 serif 字体栈；
- 不依赖第三方字体 CDN。

辨识度来自首页左侧的“时间信号线”：细线串联年份节点和文章条目，技术内容使用实心节点，人生内容使用空心节点，研究成果使用方形节点。该规则编码真实内容类型，不作为无意义装饰。

## 页面与组件

- `SiteHeader`：站名、主导航、主题切换和移动端菜单；
- `Intro`：姓名、双语短句、研究方向和主要链接；
- `TimelineFeed`：首页统一时间流；
- `PostList`：技术或人生频道列表；
- `PostMeta`：日期、类型、标签、阅读时间；
- `Prose`：中英文正文、图片、表格、引用和代码排版；
- `TableOfContents`：仅在足够长的技术文章中出现；
- `ResearchList`：研究成果与发表状态；
- `Search`：Pagefind 搜索界面；
- `SiteFooter`：版权、RSS、GitHub 和电子邮箱；
- `LegacyRedirect`：旧地址兼容页。

动效只用于主题切换、菜单状态和链接焦点；尊重 `prefers-reduced-motion`，不加入循环光效、背景粒子或模拟终端打字。

## Markdown 编辑器

旧编辑器的核心能力保留：填写标题、日期和正文，预览 Markdown，生成符合新内容模型的文章文件。它是完全在浏览器本地运行的工具，不上传文本、不持久化敏感内容，也不直接调用 GitHub API。生成结果由作者下载后自行提交到仓库。

## 异常与边界情况

- 缺少描述的旧文章在迁移脚本中根据正文生成简短摘要，并在生成后人工抽查；
- 缺少标签时使用内容类型作为最小分类，不创建 `untagged` 页面；
- 图片缺少替代文字时，根据其所在章节和图示内容补充描述；无法可靠判断时使用中性的“文章配图”并在迁移报告中列出，避免凭空解释图片；
- 草稿不进入生产构建、搜索、RSS 或站点地图；
- 内容日期使用显式时区，避免 GitHub Actions 构建时跨日；
- Pagefind 尚未生成时，开发环境显示明确说明而不是空白区域。

## 验证与验收

实施完成需满足：

1. Astro 生产构建无错误；
2. 12 篇旧文章、2 条研究成果和所有正文图片均可访问；
3. 原文章永久链接均能跳转到新地址；
4. 首页能同时展示技术、人生与研究内容，并正确区分类型；
5. 搜索、RSS、标签、深浅主题和 404 页面正常工作；
6. Markdown 编辑器可生成符合新 schema 的文章文件；
7. 桌面端、窄屏手机和系统减少动效模式通过视觉检查；
8. 键盘导航、焦点状态、颜色对比度和图片替代文本满足基本可访问性要求；
9. GitHub Actions 能将 `master` 分支构建并部署到 GitHub Pages；
10. 不包含旧模板的示例人物、示例作品和未使用的前端依赖。

## 非目标

第一版不加入评论系统、账号、数据库、邮件订阅后台、访问统计平台或内容管理系统；不自动公开尚未提供的人生记忆；不改变现有论文与技术文章的学术表述。
